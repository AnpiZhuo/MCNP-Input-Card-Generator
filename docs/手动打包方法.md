# MCNP 输入卡生成器 — 手动打包方法

> **打包方式说明**：本项目**保留手册的分步手工打包为主线**（每步人工核对成功标志；手工链也是一键链失败时的退路），
> 同时提供**一步式 `npm run build:release`**（`gui\scripts\build-release.mjs`）。两者**顺序口径已统一**（2026-09-26 修）：
> **sidecar（PyInstaller）→ 覆盖 `binaries\` → vite build → tauri build → sync-sidecar 收尾 → stage-selftest**。
>
> 背景（沿革）：早期一键脚本 `release.bat` / `scripts\release.ps1` 因 npm/npx 被执行策略禁 + Git Bash MSYS 路径转换坑而废弃删除；
> 2026-09-18/19 起了新的 `build:release`（根治"落点冲突/增量缓存/binaries 是同步源"三坑），但**它把 `vite build + tauri build` 排在
> PyInstaller 之前**，而 `tauri.conf.json` 的 `beforeBuildCommand` 含 `sync-sidecar`、正等着 `dist_sidecar\` ⇒
> **干净工作区（没有 `dist_sidecar\`）上必自我中断**（2026-09-26 打 v1.7.7 时首次即踩，只能退回本手册手工顺序）。
> **该缺陷已于 2026-09-26 修复并实测**（清空 `dist_sidecar` 与两个缓存目录后 `npm run build:release` = **EXIT 0 / 182 s**）。
> 本流程已多次成功打包验证（**最近一次 v1.7.7**，2026-09-26）。
> **版本规则（上级硬规则）**：bug 修复批默认**严禁升版**，升版仅限**上级（用户）指定** —— v1.7.7 即用户指定（含三条修复 + 09-23/24 在制批次）。
> 再次打包前先向用户确认/提升版本号（见步骤 1，**6 处/7 个字段**）。

## 1. 版本提升

**目的**：让本次产物带正确版本号。**版本规则（上级硬规则）**：bug 修复批严禁升版（恒当前版本）；仅实际新功能上线由上级指定新版本。**当前包版本 = v1.7.6**（2026-09-11，**用户指定**：源演示修复二批 + 粒子圆点化 + 一键运行 MCNP 多核 tasks；此前 1.7.5（2026-09-04，AI 接入 inputcard-mcp + 六棱柱/四面体）、1.7.4（2026-08-27 3D 预览 U 分组/窗口裁剪）、1.7.2（2026-08-18 快捷建栅元））。打包前先向用户确认目标版本号——**别自己定**（PM 曾擅自升到 1.7.2/1.7.3 属违规，已回退并记规则）。

**要改的六处**（四处 + **两个锁文件**，都必须改；以 `tauri.conf.json` 的 `package.version` 为权威，保持各处一致）：

| 文件 | 字段 |
| :--- | :--- |
| `gui\src-tauri\tauri.conf.json` | `package.version` |
| `gui\package.json` | `version`（**侧边栏版本号的唯一来源** —— `Sidebar.tsx:2` 直接 `import pkg from "../../package.json"`，故**升版后必须重新 `vite build`**，否则界面显示旧版本） |
| `gui\package-lock.json` | **两处**：顶层 `version` + `packages[""].version`（2026-09-11 v1.7.6 打包时发现本手册原先漏列；不改不影响出包，但不一致是隐患） |
| `gui\src-tauri\Cargo.toml` | `version`（**v1.6.4 曾漏改的教训**：v1.6.4 打包时此文件停在 1.6.3 未同步。虽 Tauri 以 tauri.conf.json 为权威、不影响出包，但版本不一致是隐患） |
| `README.md` | 版本徽章（**第 25 行** `Version-1.7.6` 同步改；旧记载"第 9 行 / Version-1.7.2"已于 2026-09-10 更正） |
| `gui\src-tauri\Cargo.lock` | `[[package]] name="mcnp-ui"` 的 `version`（锁文件不同步不影响出包，但不一致是隐患，一并改） |

**执行命令**（cmd 窗口内，用记事本打开改，或用编辑器改）：

```bat

notepad "d:\MCNP\PROJECT_ROOT\gui\src-tauri\Cargo.toml"

notepad "d:\MCNP\PROJECT_ROOT\gui\src-tauri\Cargo.lock"
```

**成功标志**：五个文件的版本号一致（如 `1.7.1` → `1.7.2`），格式为 `主.次.修订`。

**常见失败与解决**：

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 文件版本号不一致 | 只改了一处 | 五处都改，以 `tauri.conf.json` 为准同步其余 |
| **Cargo.toml 忘改** | **v1.6.4 曾漏**（打包时停在 1.6.3） | 三处都同步；Cargo.toml 虽不影响 Tauri 出包（tauri.conf.json 权威），但不一致是隐患，一并改 |

| 格式错误 | 输成 `1.6` / `1.7.2.1` | 改为 `主.次.修订`（如 `1.7.2`） |
| 版本号没变就出包 | 直接沿用旧版本 | 可沿用当前版本，但建议每次内容变更都提升，便于追溯 |

## 4. PyInstaller 打包 sidecar

**目的**：把 Python 后端（`mcnp_bridge.py` → `api_server.py` 常驻 5001）打成可执行的 sidecar `python.exe`（onedir 结构：小 exe + `_internal/`）。

**执行命令**（cmd 窗口内，**必须在 `gui\` 下执行**——`mcnp_sidecar.spec` 用 `os.getcwd()/..` 定位工程根，换目录会定位错）：

```bat
cd /d d:\MCNP\PROJECT_ROOT\gui
python -m PyInstaller mcnp_sidecar.spec --noconfirm --distpath dist_sidecar --workpath build_sidecar
```

> **✅ 口径统一（2026-09-26）**：`npm run build:release` 现在**逐字使用这两个路径**（`--distpath dist_sidecar` +
> `--workpath build_sidecar`），并在跑之前**把 `build_sidecar` 与 `build\mcnp_sidecar` 两个缓存目录都清掉**
> —— 此前脚本跑的是 PyInstaller **默认 workpath**（`build\mcnp_sidecar`）却只清那个目录，
> 于是"脚本路线"与"手册路线"各用各的缓存，**坑 B 的"清缓存"根本对不上**（2026-09-26 实测记录，已修）。

> **❗`--distpath dist_sidecar` 不可省（2026-09-23 实跑踩到，spec 第 130-139 行亦明令）**：
> 不加它，产物落进默认的 `gui\dist\python\` —— 而 **`vite build` 会清空 `gui\dist\`**，
> 于是"先 PyInstaller → 再 `npm run build:app`"会把刚打好的 sidecar **删掉**，同步脚本
> 随后把 `binaries\` 里**上一次的旧 python.exe** 铺进 `target\release` 并报
> "✅ 已是最新" ⇒ 打出"版本号新、后端旧"的包（spec 里点名的**坑 6.7**，冒烟才发现修复不生效）。
> 两者物理分开（`dist/` 给前端、`dist_sidecar/` 给 sidecar）后互不干扰。
>
> ⚠️ spec 注释让走的 `npm run build:sidecar` **在 `package.json` 里并不存在**
> （2026-09-23 核实：scripts 只有 `sync-sidecar`/`check-sidecar`/`verify-sidecar`/`build:app`）
> ⇒ **以上面那条带 `--distpath` 的显式命令为准**。`coll.distpath = ...` 也不行：
> COLLECT 对象没有该属性，赋值会被静默忽略。

**⚠️ 踩坑 4.1：spec 的 `_keep_py` 必须先核对**（3D 预览新增的模块，漏掉则 exe 启动即崩）：
1. 打开 `gui\mcnp_sidecar.spec`，确认 `_keep_py` 列表**包含 `"preview_cache.py"`**（它是 `gui\backend\api_server.py` 顶层 import 的，3D 预览缓存模块）。
2. 确认 `excludes` 含 `pyvista / pyvistaqt / vtk / vtkmodules / PyQt5`（排除 Qt/vtk 死代码，减小体积）。
3. 打包完成后核对产物：`gui\dist\python\_internal\app\preview_cache.py` **必须存在**。

**⚠️ 踩坑 4.2：AI 接入（inputcard-mcp）**（可选，若需要，见 `docs\inputcard-mcp.md`）：
- `gui\mcnp_sidecar.spec` 的 `_hidden` 已含 `inputcard_mcp`、`inputcard_mcp.server`（mcnp_bridge `--mcp-http` 分派用）；`mcp` 及其依赖由 PyInstaller 从 `mcp.server.fastmcp` 自动收集。
- 打包后主程序启动时会自动拉起 `--mcp-http`（本机环回 8100 /mcp），外部 AI 客户端经 http://127.0.0.1:8100/mcp 连接。主程序关闭时随之终止。
- 需在 gui\ 下执行 PyInstaller 时确保 `mcp>=1,<2` 已装（`pip install -r inputcard_mcp/requirements.txt`）。

**成功标志**（产物 onedir 结构）：
- `gui\dist_sidecar\python\python.exe`
- `gui\dist_sidecar\python\_internal\`（含 `app\`、`vendor\` 等）
- `gui\dist_sidecar\python\_internal\app\preview_cache.py` 在位（spec 自检通过）
- **本批改过的 `app\*.py` 要在位且是新版**（例：2026-09-23 批核对
  `_internal\app\step_importer_geouned.py` 含 `_PARAM_TABLE`、`geouned_worker.py` 含五区段
  `data.get("settings"|"options"|"tolerances"|"load_step"|"export")`）

**常见失败与解决**：

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 产物落进 `gui\dist\python\` | **漏了 `--distpath dist_sidecar`** | 删掉 `gui\dist\python`，按上文重跑；**别让它留着**，否则后续 `vite build` 会连它一起清掉 |
| `_internal\app\preview_cache.py` 缺失 | spec `_keep_py` 漏了 `preview_cache.py` | 在 spec `_keep_py` 补 `"preview_cache.py"` 后重跑；否则 exe 启动即崩 |
| PyInstaller 报错 | 依赖缺失 / 路径异常 | 确认在 `gui\` 下执行；`python -m PyInstaller --version` 可出版本号；看完整错误输出 |
| `dist_sidecar` 是旧的 | 上次产物残留 | `--noconfirm` 已覆盖；必要时手动删 `gui\dist_sidecar` 再跑 |
| 看不到进度、像卡死 | 用 `Select-Object -Last N` 接管道会**收完整个流才打印** | 改用 `Tee-Object -FilePath <log>` 落盘后 `Get-Content -Tail`；或探针看 `dist_sidecar` 文件数与写入时间（**注意本机 python 进程名是 `python3.13`，不是 `python`**） |

## 6.5 WebView2 固定版运行时（**没有 Edge 的机器能不能打开，就看这一步**）

**背景（2026-09-29 实测）**：界面是 WebView2 渲染的，而 WebView2 平时**由 Edge 附带安装**。
精简版/优化版 Windows 把 Edge 删掉时**连带没有** WebView2 Runtime ⇒ 双击 `MCNP 输入卡生成器.exe`
**没反应、或窗口一闪就没**（用户报的"没装 Edge 就打不开"就是这个，与后端 sidecar 无关）。

**做法**：随包分发一份微软官方「固定版运行时」（`FixedVersionRuntime`），放在
**与 exe 同级**的 `WebView2\` 目录；`gui\src-tauri\src\main.rs` 的 `prefer_bundled_webview2()`
启动时找 `<exe目录>\WebView2\msedgewebview2.exe`，找到就用官方环境变量
`WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` 指过去 —— 于是**完全不需要系统里有 Edge/WebView2**；
找不到则**回退**系统运行时（行为同旧版，不会因为漏拷目录而把本来能用的机器也弄坏）。

> **为什么不用 `tauri.conf.json` 的 `webviewInstallMode=fixedRuntime`**：那是**无条件**写死
> 目录（tauri 1.8.3 `src/app.rs:1696-1715` 在 `setup()` 里直接 `set_var`），漏拷目录时
> 连"本来能用系统运行时"的机器也一起打不开 —— 把"可选增强"变成"硬依赖"。
> 另外本项目 `bundle.active=false`（不出安装包），该配置对"免安装 onedir 交付"没有打包意义。

### 6.5.4 ★Win10 必做：给运行时目录补 AppContainer ACL

官方分发文档（Distribute your app and the WebView2 Runtime）Step 6 明写：**固定版 ≥120 在 Win10 上**

```bat
icacls "<交付目录>\WebView2" /grant *S-1-15-2-2:(OI)(CI)(RX) /grant *S-1-15-2-1:(OI)(CI)(RX) /T /C /Q

- Win11 不需要这两条（本机 Win11 26200 实测：不补也能正常起界面）；
- 诚实标注：**"不补会怎样"在本机（Win11）无法复现**，这条是按官方文档执行，不是本机实测结论。

### 8.1 启动 + 5001 探活

```

**成功标志**：`netstat` 显示 `5001` 端口 `LISTENING`；`curl` 返回含 `loaded` 的 JSON（如 `{"loaded":true,...}`）。

### 8.1b ★ WebView2 到底走的哪一份（**证明"不需要 Edge"这件事真的成立**，2026-09-29 定）

**为什么必须单独验**：本机（开发机）**本来就装了系统 WebView2**，所以"程序能打开"这件事
**不能**证明自带运行时被用上了 —— 它可能是走了系统那份。判据是子进程的**可执行文件路径**：

```powershell
# 启动部署的程序后，看它拉起来的 WebView2 进程是从哪儿跑的
Get-CimInstance Win32_Process -Filter "Name='msedgewebview2.exe'" |
  Select-Object ProcessId, ExecutablePath
```

**成功标志**：`ExecutablePath` 落在**交付目录**里，形如
`DIST_DIR\WebView2\msedgewebview2.exe`。
**失败标志**：落在 `C:\Program Files (x86)\Microsoft\EdgeWebView\Application\<版本>\` ——
说明走的是系统运行时（自带目录没找到/名字不对/没铺），到没有 Edge 的机器上照样打不开。

> 这条与"关掉系统运行时的对照实验"相比，**不动用户机器、可反复跑**，是首选判据。
> 若要在本机做更强的对照：临时把 `C:\Program Files (x86)\Microsoft\EdgeWebView\Application`
> 改名（需管理员），再启动程序 —— 能开即证明完全不依赖系统运行时；**验完立刻改回来**。

### 8.2 3D 预览出图

在程序界面打开任一卡文件并做 3D 预览，应能正常出图（几何模型渲染）。**出图即证明** sidecar 内 `freecad_preview.py`、`preview_cache.py`、`vendor\geouned\` 等全部就绪——这是对第 7 步「入口模块编译进 exe」的最终运行期验证。

> **① 后端是不是新版 → 比 sha256，不看日期**。`app\` 下松散投放的 `.py`（`_keep_py` 那批，

> **★ 更省事也更硬的替代判据（2026-09-20 补，S9 实测）**：直接 **curl 本批新增/新支持的那个端点**。
