# MCNP 输入卡生成器 — 手动打包方法

> 本说明面向**用户在 cmd 窗口中分步照做**的实操指南，把打包、部署、验证手工完成。
>
> 背景：`release.bat` 自动化发版已**停止使用**（自检环节后端拉不起 5001 未解决 + Git Bash 有 MSYS 路径转换坑）。本文档取代 `README-release.md` 描述的 `release.bat` 一键流程，改为**手动分步出包**。仓库根 `release.bat` / `README-release.md` 仅作参考，**不要依赖自动化脚本**。
>
> 本流程已按 v1.6.3 及重打包两次成功手动打包验证，产物均成功部署到 `D:\MCNP\MCNP输入卡生成器` 并通过冒烟验证。当前已提交版本 **1.6.4**（commit `29d9d93`）；**下次打包目标版本 = 1.7.0**（网格计数可视化大功能，用户 2026-08-14 指定，非 1.6.5）。再次打包前先确认/提升版本号（见步骤 1，三处+README）。

## 1. 版本提升

**目的**：让本次产物带正确版本号。当前已提交版本为 **1.6.4**；**下次打包目标版本 = 1.7.0**（网格计数可视化大功能，用户 2026-08-14 指定），若再打包且内容有变化，先提升版本。

**要改的三处 + README 徽章**（都必须改，`release.bat` 时代以 `tauri.conf.json` 为权威，此处同样保持各处一致）：

| 文件 | 字段 |
| :--- | :--- |
| `gui\src-tauri\tauri.conf.json` | `package.version` |
| `gui\package.json` | `version` |
| `gui\src-tauri\Cargo.toml` | `version`（**v1.6.4 曾漏改的教训**：v1.6.4 打包时此文件停在 1.6.3 未同步。虽 Tauri 以 tauri.conf.json 为权威、不影响出包，但版本不一致是隐患） |
| `README.md` | 版本徽章（第 9 行 `Version-1.6.4` 同步改） |

**执行命令**（cmd 窗口内，用记事本打开改，或用编辑器改）：

```bat

notepad "d:\MCNP\输入卡生成器源码\gui\package.json"
notepad "d:\MCNP\输入卡生成器源码\gui\src-tauri\Cargo.toml"

```

**成功标志**：四个文件的版本号一致（如 `1.6.4` → `1.7.0`），格式为 `主.次.修订`。

**常见失败与解决**：

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 文件版本号不一致 | 只改了一处 | 三处+README 都改，以 `tauri.conf.json` 为准同步其余 |
| **Cargo.toml 忘改** | **v1.6.4 曾漏**（打包时停在 1.6.3） | 三处都同步；Cargo.toml 虽不影响 Tauri 出包（tauri.conf.json 权威），但不一致是隐患，一并改 |

| 版本号没变就出包 | 直接沿用旧版本 | 可沿用当前版本，但建议每次内容变更都提升，便于追溯 |

> 版本号改动涉及 git 跟踪文件，出包验证通过后请一并提交。

## 4. PyInstaller 打包 sidecar

**目的**：把 Python 后端（`mcnp_bridge.py` → `api_server.py` 常驻 5001）打成可执行的 sidecar `python.exe`（onedir 结构：小 exe + `_internal/`）。

**执行命令**（cmd 窗口内，**必须在 `gui\` 下执行**——`mcnp_sidecar.spec` 用 `os.getcwd()/..` 定位工程根，换目录会定位错）：

```bat
cd /d d:\MCNP\输入卡生成器源码\gui
python -m PyInstaller --noconfirm mcnp_sidecar.spec
```

**⚠️ 踩坑 4.1：spec 的 `_keep_py` 必须先核对**（3D 预览新增的模块，漏掉则 exe 启动即崩）：
1. 打开 `gui\mcnp_sidecar.spec`，确认 `_keep_py` 列表**包含 `"preview_cache.py"`**（它是 `gui\backend\api_server.py` 顶层 import 的，3D 预览缓存模块）。
2. 确认 `excludes` 含 `pyvista / pyvistaqt / vtk / vtkmodules / PyQt5`（排除 Qt/vtk 死代码，减小体积）。
3. 打包完成后核对产物：`gui\dist\python\_internal\app\preview_cache.py` **必须存在**。

**成功标志**（产物 onedir 结构）：
- `gui\dist\python\python.exe`
- `gui\dist\python\_internal\`（含 `app\`、`vendor\` 等）
- `gui\dist\python\_internal\app\preview_cache.py` 在位（spec 自检通过）

**常见失败与解决**：

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| `_internal\app\preview_cache.py` 缺失 | spec `_keep_py` 漏了 `preview_cache.py` | 在 spec `_keep_py` 补 `"preview_cache.py"` 后重跑；否则 exe 启动即崩 |
| PyInstaller 报错 | 依赖缺失 / 路径异常 | 确认在 `gui\` 下执行；`python -m PyInstaller --version` 可出版本号；看完整错误输出 |
| `dist\python` 是旧的 | 上次产物残留 | `--noconfirm` 已覆盖；必要时手动删 `gui\dist\python` 再跑 |

## 5. sidecar 替换进 binaries

**目的**：把 PyInstaller 产物按 Tauri 约定的 sidecar 文件名与布局放进 `gui\src-tauri\binaries\`，供 Rust 编译期打包进 exe。

**执行命令**（cmd 窗口内）：

```bat
:: 5a. 清空旧 binaries
rmdir /s /q "d:\MCNP\输入卡生成器源码\gui\src-tauri\binaries"
mkdir "d:\MCNP\输入卡生成器源码\gui\src-tauri\binaries"

:: 5b. python.exe 复制为重命名后的 sidecar exe
copy /y "d:\MCNP\输入卡生成器源码\gui\dist\python\python.exe" "d:\MCNP\输入卡生成器源码\gui\src-tauri\binaries\python-x86_64-pc-windows-msvc.exe"

:: 5c. _internal 完整复制（保留 onedir 结构，绝不能只拷 exe）
xcopy /e /i /y "d:\MCNP\输入卡生成器源码\gui\dist\python\_internal" "d:\MCNP\输入卡生成器源码\gui\src-tauri\binaries\_internal"
```

**成功标志**：
- `gui\src-tauri\binaries\python-x86_64-pc-windows-msvc.exe`
- `gui\src-tauri\binaries\_internal\`（完整目录树）
- `gui\src-tauri\binaries\_internal\app\preview_cache.py` 在位

**常见失败与解决**：

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 只看到 exe、没有 `_internal` | 忘了 xcopy | 补 `xcopy` 一步；sidecar 是 `python.exe + _internal/` 结构，缺一不可 |
| binaries 里有旧残留 | 没先清空 | 先 `rmdir` 再建，保证是本次全新产物 |

## 6. tauri build（Rust 编译）

**目的**：把前端 `dist/` + Rust 壳 + sidecar 编译成最终可执行程序。

**执行命令**（cmd 窗口内，先设 Rust 环境变量再跑）：

```bat
cd /d d:\MCNP\输入卡生成器源码\gui
set RUSTUP_HOME=D:\rust\rustup
set CARGO_HOME=D:\rust\cargo
npm run tauri build
```

**⚠️ 踩坑 6.1：`bundle.active=false`** → **不生成安装包**，产物直接落在 `gui\src-tauri\target\release\`，**从 `target\release\` 复制 onedir**，不要去看/依赖 `bundle\` 目录（`bundle\` 为空是正常现象）。

**成功标志**（产物 onedir 结构，全在 `gui\src-tauri\target\release\` 下）：
- `MCNP 输入卡生成器.exe`
- `python.exe`（sidecar）
- `_internal\`（完整目录树）

### 6.2 ⚠️ sidecar 时效校验（tauri build 增量编译坑，部署前必查）

**目的**：`tauri build` 是**增量编译**——它重建主 exe，但**不会自动把新 sidecar 覆盖进 `target\release\`**。若 `target\release\python.exe` / `target\release\_internal\` 是**陈旧旧版**（mtime 停留在上次），部署复制的就是旧 sidecar → 产物"版本号新、后端旧"（旧代码、缺本次修复）。

**校验命令**（cmd 窗口内，对比 mtime/大小）：

```bat
:: 新 sidecar（第 5 步产物）与 target\release 中 sidecar 对比
dir "d:\MCNP\输入卡生成器源码\gui\src-tauri\binaries\python-x86_64-pc-windows-msvc.exe"
dir "d:\MCNP\输入卡生成器源码\gui\src-tauri\target\release\python.exe"
dir "d:\MCNP\输入卡生成器源码\gui\src-tauri\target\release\_internal"
```

**成功标志**：`target\release\python.exe` 与 `target\release\_internal\` 的 mtime/大小**等于刚 PyInstaller 产出的新 sidecar**（即与 `binaries\` 下的一致），而不是停留在旧日期。

**若不匹配（sidecar 没刷新），手动强制覆盖后再部署**：

```bat
:: 把新 sidecar 覆盖到 target\release（备份旧的在 target\release\_internal 原本就在，无需动主 exe）
copy /y "d:\MCNP\输入卡生成器源码\gui\src-tauri\binaries\python-x86_64-pc-windows-msvc.exe" "d:\MCNP\输入卡生成器源码\gui\src-tauri\target\release\python.exe"
rmdir /s /q "d:\MCNP\输入卡生成器源码\gui\src-tauri\target\release\_internal"
xcopy /e /i /y "d:\MCNP\输入卡生成器源码\gui\src-tauri\binaries\_internal" "d:\MCNP\输入卡生成器源码\gui\src-tauri\target\release\_internal"
```

覆盖后再 `dir` 复核 mtime 已更新，然后进入步骤 7 部署。

**常见失败与解决**：

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| `target\release\python.exe` 是旧日期（如 08-04） | tauri build 增量编译没刷新 sidecar | 按上面手动覆盖命令强制覆盖，再 `dir` 复核 |
| `target\release\_internal\` 是旧日期（如 08-12） | 同上 | 删掉旧 `_internal` 后用 `binaries\_internal` xcopy 覆盖 |
| 部署了但功能还是旧行为 | 上一行的坑没排查 | 回 6.2 校验 sidecar 时效；这就是"版本号新、后端旧"的根因 |

**其他常见失败与解决**：

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| tauri build 报 Rust 错 | Rust 工具链缺失/损坏 | 确认 `D:\rust\cargo\bin\cargo.exe` 存在；检查 cargo 报错 |
| 找不到 `MCNP 输入卡生成器.exe` | 在 `bundle\` 里找 | 产物在 `target\release\`；`bundle\` 为空正常 |
| 编译很慢 | Rust 首次全量编译 | 5~15 分钟属正常；后续是增量编译会快 |

## 7. 部署到交付目录

**目的**：把最终 onedir 产物完整复制到 `D:\MCNP\MCNP输入卡生成器`，作为交付版本。

> **部署前先做步骤 6.2 的 sidecar 时效校验**：确认 `target\release\python.exe` + `target\release\_internal\` 是刚打包的新 sidecar（mtime 非旧日期），否则手动覆盖后再复制，避免"版本号新、后端旧"。

**执行命令**（cmd 窗口内）：

```bat
:: 7a. 若正在运行已部署程序，先关闭（占用文件会锁目录，导致清空失败）
taskkill /f /im "MCNP 输入卡生成器.exe" >nul 2>&1
for /f "tokens=5" %p in ('netstat -ano ^| findstr ":5001" ^| findstr "LISTENING"') do taskkill /f /pid %p >nul 2>&1

:: 7b. 清空交付目录
rmdir /s /q "D:\MCNP\MCNP输入卡生成器"
mkdir "D:\MCNP\MCNP输入卡生成器"

:: 7c. 完整复制 onedir 三件套
copy /y "d:\MCNP\输入卡生成器源码\gui\src-tauri\target\release\MCNP 输入卡生成器.exe" "D:\MCNP\MCNP输入卡生成器\MCNP 输入卡生成器.exe"
copy /y "d:\MCNP\输入卡生成器源码\gui\src-tauri\target\release\python.exe" "D:\MCNP\MCNP输入卡生成器\python.exe"
xcopy /e /i /y "d:\MCNP\输入卡生成器源码\gui\src-tauri\target\release\_internal" "D:\MCNP\MCNP输入卡生成器\_internal"
```

**成功后核对在位清单**（cmd 窗口内逐个确认）：

```bat
dir "D:\MCNP\MCNP输入卡生成器\MCNP 输入卡生成器.exe"
dir "D:\MCNP\MCNP输入卡生成器\python.exe"
dir "D:\MCNP\MCNP输入卡生成器\_internal\app\preview_cache.py"
dir "D:\MCNP\MCNP输入卡生成器\_internal\vendor\geouned"
```

| 核对项 | 说明 |
| :--- | :--- |
| `MCNP 输入卡生成器.exe` | 主程序 |
| `python.exe` | sidecar（与 `_internal/` 配套，缺一不可） |
| `_internal\app\preview_cache.py` | spec 自检：3D 预览缓存模块已打入（漏则 exe 启动即崩） |
| `_internal\vendor\geouned\` | GEOUNED 纯 Python 包随程序分发 |

> **关于 `api_server.py` / `mcnp_bridge.py`**：`mcnp_bridge.py` 是 PyInstaller 的**入口脚本**，`api_server.py` 是它 import 的模块，二者被**编译进 `python.exe` 内部的归档（PYZ）**，**不落盘为 `_internal` 下的独立 `.py` 文件**——所以 `_internal\app\api_server.py`、`_internal\backend\mcnp_bridge.py` 不存在属正常。要验证它们正确打进去，靠步骤 8 的**运行期冒烟**（exe 能拉起 5001 即证明入口与模块齐全）。

**常见失败与解决**：

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 清空目录失败 | 有进程占用（正在运行的程序/后台 sidecar） | 先 taskkill 主程序 + 占用 5001 的进程，等 2 秒再清 |
| 缺 `preview_cache.py` | 第 4 步 spec 没核对 / 第 5 步没完整复制 | 回到第 4/5 步重做 |
| `vendor\geouned` 缺失 | spec 里 `GEOUNED_SRC` 路径不可达 | 确认 `D:\MCNP\GEOUNED\geouned` 存在，重跑 PyInstaller |

## 8. 冒烟验证

**目的**：确认部署产物真实可用（sidecar 拉起、后端就绪、3D 预览能出图）。

### 8.1 启动 + 5001 探活

**执行命令**（cmd 窗口内）：

```bat
:: 启动部署的程序（会弹窗）
start "" "D:\MCNP\MCNP输入卡生成器\MCNP 输入卡生成器.exe"

:: 等待数秒后检查 5001 端口是否就绪（多试几次，最多约 90 秒）
netstat -ano | findstr 5001
```

或直接探活后端健康端点：

```bat
curl http://127.0.0.1:5001/api/xsdir-check
```

**成功标志**：`netstat` 显示 `5001` 端口 `LISTENING`；`curl` 返回含 `loaded` 的 JSON（如 `{"loaded":true,...}`）。

### 8.2 3D 预览出图

在程序界面打开任一卡文件并做 3D 预览，应能正常出图（几何模型渲染）。**出图即证明** sidecar 内 `freecad_preview.py`、`preview_cache.py`、`vendor\geouned\` 等全部就绪——这是对第 7 步「入口模块编译进 exe」的最终运行期验证。

### 8.3 关闭清理

**执行命令**：

```bat
taskkill /f /im "MCNP 输入卡生成器.exe"
for /f "tokens=5" %p in ('netstat -ano ^| findstr ":5001" ^| findstr "LISTENING"') do taskkill /f /pid %p
```

**成功标志**：进程已终止，5001 释放，无残留。

**常见失败与解决**：

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |

## 9. 踩坑清单（全部血泪教训，务必逐条对照）

| # | 踩坑 | 说明 |
| :--- | :--- | :--- |
| 1 | **Git Bash 跑 .bat 会被 MSYS 吞 `/c` / `//`** | Git Bash 下 `cmd /c` 的单斜杠会被 MSYS 路径转换吞掉、`cmd //c` 又报「找不到 // 文件」。**用 cmd 窗口直接跑，别用 Git Bash**；若必须在 Git Bash 下跑，用 `MSYS_NO_PATHCONV=1 cmd /c ...` 关掉路径转换。 |
| 2 | **`tauri.conf.json` 的 `bundle.active=false`** | **不生成安装包**，产物在 `gui\src-tauri\target\release\`，**从 `target\release\` 复制 onedir**，不依赖 `bundle\` 目录（`bundle\` 为空正常）。 |
| 3 | **sidecar 是 `python.exe` + `_internal/` 结构** | 复制要完整（onedir 结构），**绝不能只拷 exe** 忘掉 `_internal`，否则启动即崩。 |
| 4 | **spec 必须先核对含最新模块** | `gui\mcnp_sidecar.spec` 的 `_keep_py` 必须含 `preview_cache.py`（3D 预览新增，`api_server.py` 顶层 import），漏掉则 exe 启动即崩；同时 `excludes` 必须含 PyQt5/vtk。核对产物 `_internal\app\preview_cache.py` 存在。 |
| 5 | **冒烟必须做** | 起 exe → 5001 探活 → 3D 预览出图。这是确认「`mcnp_bridge.py`/`api_server.py` 已编译进 exe」的唯一运行期手段。 |
| 6 | **版本提升三处+README 都要改** | `gui\src-tauri\tauri.conf.json`（`package.version`）+ `gui\package.json`（`version`）+ `gui\src-tauri\Cargo.toml`（`version`）+ `README.md` 徽章同步改；release 时代以 `tauri.conf.json` 为准，此处保持各处一致（**v1.6.4 曾漏 Cargo.toml，停在 1.6.3**）。 |
| 7 | **tauri build 增量编译不会刷新 target\release 里的 sidecar** | `npm run tauri build` 重建主 exe，但 `target\release\python.exe` + `target\release\_internal\` 可能是**陈旧旧版**（mtime 停留在上次），部署复制的就是旧 sidecar → "版本号新、后端旧"（缺本次修复）。**部署前必须 6.2 核对 mtime/大小**；不匹配则手动把 `binaries\` 的 sidecar 覆盖到 `target\release\` 再部署。 |
